# NomadsAI

AI-assisted travel planning with a Next.js frontend and FastAPI backend. Gemini is the sole supported generative AI provider.

## Stack

- Frontend: Next.js, React and TypeScript
- Backend: FastAPI and Python
- AI: Google Gemini Developer API
- HTTP client: httpx
- Deployment: Vercel (frontend) and Render (backend)

## Features

- AI-generated travel itineraries
- Conversational travel planning
- Destination context and travel signals
- Backend health and AI configuration endpoints

## Configure Gemini

Create an API key in [Google AI Studio](https://aistudio.google.com/apikey).

Set these variables in the backend environment:

```dotenv
GEMINI_API_KEY=your_gemini_api_key
GEMINI_MODEL=gemini-3.8-flash
CORS_ORIGINS=http://localhost:3000
```

The default model can be changed with `GEMINI_MODEL`. The API key must remain server-side. Do not add it to frontend environment variables, source control, browser code, or client requests.

NomadsAI sends requests to the Gemini Developer API `generateContent` endpoint using the `x-goog-api-key` header. The backend converts its internal chat messages into Gemini's `systemInstruction` and `contents` format.

## Local development

### Backend

```bash
cd backend
python -m venv .venv
# Windows: .venv\\Scripts\\activate
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Add GEMINI_API_KEY to .env
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Set the frontend API base URL to the backend address using the project's existing frontend configuration.

## API health

- `GET /healthz`: application health
- `GET /api/ai-status`: Gemini configuration and selected model
- `GET /api/pipeline-status`: pipeline status

The AI status endpoint never returns the API key.

## Deployment

Configure `GEMINI_API_KEY`, `GEMINI_MODEL`, and `CORS_ORIGINS` in the backend hosting provider's environment settings. Configure the frontend's backend URL separately in Vercel.

## Security notes

- Persistent memory endpoints are currently disabled until the project has authentication and per-user ownership checks.
- Chat session identifiers are generated by the backend. Client-provided identity and provider credentials are not accepted.

- Keep Gemini credentials in backend environment variables.
- Rotate a key immediately if it is accidentally committed or exposed.
- Restrict the key to the Gemini API in Google AI Studio / Google Cloud where available.
- Use an explicit list of trusted frontend origins in `CORS_ORIGINS`, not a wildcard.
- Public chat and itinerary-generation routes have per-IP limits. Configure `REDIS_URL` or `RATE_LIMIT_STORAGE_URI` for shared limits across multiple backend instances; the in-memory fallback is intended only for development or a single instance.
